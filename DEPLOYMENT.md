# Deployment Guide — BGM Pro Sports

Standard workflow: **Develop → Commit → Push → Hosting Pull → Deploy**

> ⚠️ **Never deploy without a backup.** See [`BACKUP.md`](BACKUP.md) first.

---

## 1. Deployment workflow

### 1.1 Development → GitHub

```bash
# Stage (git-ignored files are automatically skipped)
git add -A

# Review EXACTLY what will be committed — check for secrets
git status
git diff --cached --stat

# Commit with a meaningful message
git commit -m "feat: add product filter by brand"

# Push
git push origin main
```

**Commit message convention**

| Prefix | Use |
|---|---|
| `feat:` | New feature |
| `fix:` | Bug fix |
| `chore:` | Maintenance / config |
| `docs:` | Documentation only |
| `refactor:` | Code change, no behaviour change |
| `hotfix:` | Urgent production fix |

### 1.2 Hosting pull → deploy

```bash
# On the server, from the project root
cd /var/www/bgmprosports

# BACKUP FIRST (see BACKUP.md)
./backup.sh

# Pull the new code
git fetch origin
git log --oneline HEAD..origin/main   # review what's incoming
git pull origin main

# Install any new PHP dependencies
composer install --working-dir=main --no-dev --optimize-autoloader

# Run migrations ONLY after reviewing them
php main/artisan migrate --force

# Clear and rebuild caches
php main/artisan optimize:clear
php main/artisan optimize
php main/artisan view:clear

# Ensure storage link exists (public path = project root)
php main/artisan storage:link
```

### 1.3 First-time server setup

```bash
git clone https://github.com/vishnupriyangamer003-rgb/bgmprosports.git
cd bgmprosports

composer install --working-dir=main --no-dev --optimize-autoloader

cp main/.env.example main/.env
php main/artisan key:generate          # always generate a FRESH key

# Edit main/.env:
#   APP_URL=https://your-domain.com
#   APP_ENV=production
#   APP_DEBUG=false                    # MUST be false in production
#   DB_HOST / DB_DATABASE / DB_USERNAME / DB_PASSWORD
#   ADMIN_DIR=<your-secret-admin-path>

php main/artisan migrate --force
php main/artisan storage:link
php main/artisan optimize

# Restore media + database from backup (see BACKUP.md)
```

## 2. Environment configuration

| Variable | Production value |
|---|---|
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_URL` | `https://your-domain.com` |
| `APP_KEY` | generated by `php artisan key:generate` |
| `DB_*` | your hosting database credentials |
| `ADMIN_DIR` | custom secret path (do **not** leave as `admin`) |
| `SESSION_SECURE_COOKIE` | `true` (HTTPS only) |
| `SESSION_HTTP_ONLY` | `true` |

`.env` is git-ignored. On the server, keep it readable only by the web user:

```bash
chmod 640 main/.env
chown www-data:www-data main/.env
```

## 3. File permissions (Linux)

```bash
# Project root
chown -R www-data:www-data /var/www/bgmprosports
find /var/www/bgmprosports -type d -exec chmod 755 {} \;
find /var/www/bgmprosports -type f -exec chmod 644 {} \;

# Writable runtime + upload directories ONLY
chmod -R 775 /var/www/bgmprosports/main/storage
chmod -R 775 /var/www/bgmprosports/main/bootstrap/cache
chmod -R 775 /var/www/bgmprosports/storage          # uploads
```

> Do **not** `chmod -R 777` — it is a security risk.

## 4. Caching & optimisation

```bash
php main/artisan config:cache      # caches configuration
php main/artisan route:cache       # caches routes
php main/artisan view:cache        # compiles Blade templates
php main/artisan optimize          # all of the above + composer dump-autoload

# After ANY .env change you MUST clear the config cache:
php main/artisan config:clear
```

## 5. Branch management

| Branch | Purpose | Deploys to |
|---|---|---|
| `main` | Stable, releasable code | Production |
| `develop` | Integration branch | Staging (optional) |
| `feat/*` | Feature work | — |
| `fix/*` | Bug fixes | — |
| `hotfix/*` | Urgent production fix | Production |

```bash
# Start a feature
git checkout main && git pull
git checkout -b feat/product-search

# Merge back
git checkout main
git merge --no-ff feat/product-search
git push origin main
```

**Never** commit directly to `main` for non-trivial changes, and **never force-push** `main`.

## 6. Safe pull / push rules

```bash
# Before pulling — always have a backup (BACKUP.md)
# Before pushing — always review
git diff --cached --stat
git status

# Never do this on main:
#   git push --force origin main      ← rewrites shared history
#   git add -f <sensitive-file>       ← bypasses .gitignore
```

Pull on the server during a maintenance window if migrations are involved.

## 7. Rollback strategy

### 7.1 Roll back code only (no schema change)

```bash
# On the server
cd /var/www/bgmprosports

git log --oneline -10               # find the last good commit
git checkout <good-sha>             # detached HEAD = quick rollback
# or move the branch pointer:
git reset --hard <good-sha>
git push --force-with-lease origin main   # ONLY if you must sync the remote

php main/artisan optimize:clear && php main/artisan optimize
```

### 7.2 Roll back code AND database

> Requires a database backup taken **before** the bad deploy.

```bash
# 1. Roll back code (above)
# 2. Restore the pre-deploy database dump (see BACKUP.md §3)
mysql -u <user> -p <database> < backup/bgmprosports_YYYY-MM-DD.sql
# 3. Restore media if it changed
# 4. Clear caches
php main/artisan optimize:clear && php main/artisan optimize
```

### 7.3 Emergency rollback checklist

1. ✅ Put site in maintenance mode: `php main/artisan down`
2. ✅ Restore code to last known good commit
3. ✅ Restore database from pre-deploy dump (if schema changed)
4. ✅ Restore media (if changed)
5. ✅ Clear all caches
6. ✅ `php main/artisan up`
7. ✅ Verify homepage, login, checkout

---

## 8. Pre-deploy checklist

- [ ] Backup completed (code + database + media) — `BACKUP.md`
- [ ] `git diff --cached --stat` reviewed; **no `.env` or secrets**
- [ ] Migrations reviewed; `--force` only after review
- [ ] `.env` on server: `APP_DEBUG=false`, correct `APP_URL`
- [ ] New `APP_KEY` **not** required (key is per-environment, never in Git)
- [ ] Caches cleared and rebuilt
- [ ] `storage` link present; `storage/` writable
- [ ] Rollback commit SHA noted **before** deploying
